# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — production build to `dist/` (Vercel uses this; `vercel.json` sets SPA rewrite)
- `npm run preview` — serve built `dist/`
- `npm run generate` — rebuild `public/data/quizzes.json` (Gujarati) and `public/data/quizzes.en.json` (English)
- `npm run fetch-text` — download full Gujarati + English text of all 273 Vachanamrut into `scripts/.cache/` (gitignored; skips cached files; ~10 min fresh)
- `npm run tag-subjects` — rebuild `scripts/subjects.json` from the cached Gujarati text
- `npm run build-extra` — rebuild `scripts/vachanamrut-source-extra.json` (Gujarati source for the 11 additional Vachanamrut) from the cache
- `npm run build-study` — rebuild `scripts/study-source.json` (all bold teachings + sabha questions per language, from the cache)
- `npm run build-en` — rebuild `scripts/vachanamrut-source-en.json` from the cached English text
- `npm run fetch-adhiveshan` — download the 100 Adhiveshan 2025 Satsang Prasang pages (gu + en) from anirdesh into `scripts/.cache/adhiveshan/` (skips cached, 1 s between requests)
- `npm run build-adhiveshan` — rebuild `public/data/adhiveshan.json` / `adhiveshan.en.json` from that cache
- `npm run build-videos` — rebuild `public/data/videos.json` (Guruhari Ashirwad video library) from `scripts/guruhari-videos.json` + `scripts/video-topics.mjs`

Full pipeline: `fetch-text` → `tag-subjects` → `build-extra` → `build-en` → `build-study` → `build-askers` → `generate`. Only `generate` is needed when just the generator changes; the committed JSON files are its inputs.

No test runner or linter is configured. The generator's built-in coverage checks (throws if any Vachanamrut is missing from the quizzes or title quizzes) are the main correctness gate — run `npm run generate` after touching the generator or source data.

## Architecture

Static React 18 + Vite site, no backend, no router library. Bilingual: Gujarati (default) and English. The site is named **અક્ષરજ્ઞાન / Akshargnan** (`appName`/`appAlt` in `i18n.js`, `index.html`, favicon); the header has four sections: Vachanamrut Quiz, પ્રાપ્તિનો વિચાર, અધિવેશન પ્રસંગ and ગુરુહરિ આશીર્વાદ વિડિયો.

**Numbering (`scripts/vachnos.mjs`):** shared by every script. `vachno` is anirdesh's number: 1–262 standard, 264–274 the 11 additional Vachanamrut of the BAPS edition (Amdavad 4–8 = 264–268, Ashlali 1 = 269, Jetalpur 1–5 = 270–274; 263 ભૂગોળ-ખગોળ is excluded). `SECTIONS` holds each section's vachno `ranges` (Amdavad is non-contiguous) in BAPS display order; use `sectionOfNo`/`positionOf`, never vachno arithmetic. Askers of the extras are hand-entered in `EXTRA_ASKERS`. The app gets `section` ids on `data.vachanamruts` and `count` on `data.sections`.

**Data pipeline (build-time, offline):**
`scripts/vachanamrut-source.json` + `vachanamrut-source-extra.json` (Gujarati: ref, title, datePhrase, teachings, askers) and `scripts/vachanamrut-source-en.json` (English, same shape minus ref) → `scripts/generate-quizzes.mjs` → one minified, committed data file per language. The generator:
- Defines `SECTIONS` (id, Gujarati/English name, vachno range) — the single source of section boundaries — and a `LANGS` table holding every per-language string (question templates, quiz titles, refs, links, output file). English refs are built as `Gadhada I-1`, `Sarangpur-7`; English quiz ids get an `en-` prefix so saved scores don't collide.
- `build(lang)` resets the seeded RNG per language, so output is deterministic. Keep output stable for unchanged inputs (saved scores are keyed by quiz id); add any new generation step *after* existing ones so the RNG sequence isn't shifted.
- Builds up to 5 question types per Vachanamrut (`title-to-ref`, `ref-to-title`, `date`, `teaching`, `asker`); question id is `${vachno}-${type}`. Distractors prefer same-section items.
- `cleanAskerGu` heuristically filters scraped Gujarati asker phrases (prefix stripping, ergative-suffix normalization, name-ending whitelist) — fragile; check `askers=` in the output after edits.
- Chunks each section's shuffled questions into quizzes of ~`QUIZ_SIZE` (25), then builds **title quizzes** (`kind: 'titles'`, type `section-title`): exactly one question per Vachanamrut, asked by position in its section ("સારંગપુરના ૭મા વચનામૃતનું શીર્ષક કયું છે?" / "…the 7th Vachanamrut of Sarangpur?").
- Then **topic quizzes** (`kind: 'topics'`, type `topic`, id `${vachno}-topic-${k}`): each title is split into topics (on `;`, and in Gujarati on `,` only when every piece ends in `નું`), one question per topic ("કયા વચનામૃતમાં મન જીત્યાની વાત કરી છે?") answered with the ref. Wrong answers exclude other Vachanamrut sharing the same topic (e.g. અન્વય-વ્યતિરેકનું is GP-7 and Sarangpur-5). Phrasing lives in `LANGS.*.topicQ`/`topicSplit`.
- Then **study quizzes** (`kind: 'study'`, types `teaching`/`prashna`) from `scripts/study-source.json`: every bold teaching and every question asked in the sabha. `build-study-source.mjs` drops sabha questions that need context (short + pronoun, fragments, "of the two") or repeat across Vachanamrut, and records `alsoIn` (other Vachanamrut containing the same passage) so they are never wrong answers.
- Then **content quizzes** (`kind: 'study'`, type `content`, title "… — વિષયવસ્તુ ક્વિઝ") from `scripts/content-questions.json`, hand/AI-written from the full text. Every question must carry `evidence` copied word for word from that Vachanamrut; with the cache present the generator throws on any evidence not found. `options[0]` is the correct one. The quiz shows the evidence after answering. Wrong options are re-chosen by `contentOptions` (own seeded RNG per question id, so other quizzes are untouched): hand-written wrong options are kept when their length is within 0.45–2.2× the correct one, the rest are correct answers of other content questions (same Vachanamrut → same section → any) ranked by similar length and form (list/comma count, ending, word count), never text found in the question's evidence or overlapping the correct answer. This removed the "correct = longest" giveaway (78% → ~31%). All 273 Vachanamrut are covered in Gujarati (~1,100 questions); English has none yet. Evidence must be plain text from the cache: avoid copying spans containing zero-width joiners (e.g. `શ્રીમદ્‌ભાગવત`) or curly apostrophes unless copied byte-exact.
- Last, **mixed title quizzes** (`kind: 'titles'`, id `titles-mix-<n>`, no `section`): the same title questions shuffled across all sections into ~25-question quizzes (11). Home labels them "સર્વ પ્રકરણ — મિશ્ર"; the random `#/title-mix` practice dedupes questions by id since they repeat across both title quiz sets.
- Last, **Ramayan / Mahabharat quizzes** (`kind: 'ramayan' | 'mahabharat'`, `section` = Kanda/Parva id, question `type: 'epic'`, ids `<epic>-<part>-q<n>`) from `scripts/epic-ramayan.json` / `epic-mahabharat.json` (`{ epic, parts, questions: [{ p, gu: [q, correct, w1, w2, w3], en: [...] }] }`, written from well-known Valmiki/Vyasa facts; wrong options of the same kind). Options use a per-question seed, so appending questions never reshuffles others; `data.epics` lists the parts. Home tabs `#/home/ramayan` / `#/home/mahabharat` use the parts as chips; the quiz shows "સંદર્ભ: <epic> — <part>" instead of a Vachanamrut link; excluded from Vachanamrut practice. Append questions per part and keep the numbering (ids follow file order within a part).
- Then **subject quizzes** (`kind: 'subject'`, `subject` id, no `section`): "which of these deals with subject X?" for every member of each hand-entered subject; wrong answers are non-members. Shown on the subject page, not on Home; excluded from practice and random subject quizzes.

**English source (`scripts/build-en-source.mjs`):** title from anirdesh's English page; date, askers and teaching extracted by regex from the English text. English paragraphs don't align 1:1 with Gujarati ones, so the teaching excerpt is taken from the same *relative position* as the bold Gujarati teaching, with narration lead-ins stripped and narration-only excerpts dropped.

**Subjects (વિષય):** `scripts/tag-subjects.mjs` scores each Gujarati text against per-subject keyword lists (`SUBJECTS`, English names in `EN`). A subject is tagged when its keyword density is ≥ `RATIO`× the corpus mean, max 5 per Vachanamrut, min 1. Subjects with `near: 'divine'` (the પ્રગટ-પ્રત્યક્ષ subject) count a keyword only if a word for Bhagwan/Sant/Bhakt (`NEAR_DIVINE`) is in the same sentence nearby. It's an automatic approximation and the UI says so. `scripts/subjects-manual.json` (`{subjectId: [vachno…]}`, entered by hand from the BAPS Vachanamrut Study App) overrides the automatic result per subject; those get `source: 'manual'` and no "approximate" note/≈ mark in the UI. Lists typed from the app with its abbreviations ("ગ.પ્ર. (1,4)") live in `scripts/subjects-app-lists.mjs`; `npm run import-subjects` converts them into `subjects-manual.json` and rejects out-of-range numbers. Rerun `tag-subjects` then `generate` after either changes. All subjects except પ્રગટ-પ્રત્યક્ષ (not in the app) are manual now. Tags are language-independent; both data files carry them.

**Runtime (`src/`):**
- `i18n.js` holds all UI strings for both languages; components call `useLang()` for `t(key, vars)`, `num()` (Gujarati digits in gu) and `link(vachno)` (anirdesh in the current language). Never hardcode UI text in components. Language is stored via `storage.js` and switched from the top bar; `App.jsx` then fetches the other data file (`DATA_URL`) and leaves any open `#/quiz/<id>` page, since ids differ per language.
- `App.jsx` does hash routing: `#/`, `#/home/titles` / `#/home/topics` (title / topic quiz tabs), `#/subjects[/<id>]`, `#/subject-quiz/<id>` (20 random title/teaching questions from that subject's Vachanamrut), `#/quiz/<id>`, `#/practice/<sectionId|all>`, `#/title-mix` (20 random title questions from all sections, button on the શીર્ષક tab), `#/titles` (searchable index — unrelated to title quizzes). Practice and subject quizzes are built client-side and not scored (ids start with `practice`). Both quiz kinds share `data.quizzes`; UI separates them by `q.kind` (absent = knowledge, `titles`, `topics`); practice and random subject quizzes exclude `titles` and `subject`. Home has 5 tabs (`#/home/<kind>`); the subject tab filters by subject instead of section.
- `components/Quiz.jsx` runs a quiz (keyboard 1–4/Enter, review-wrong-only rounds) and saves scores via `storage.js`, skipped for practice ids and review rounds.
- `storage.js` wraps localStorage under one key `vachanamrut-quiz:v1` (`{ scores: {quizId: {best,last,attempts}}, theme, lang }`), every access try/caught.
- **પ્રાપ્તિનો વિચાર section** (`#/prapti[/<from>]`, `components/Prapti.jsx`): the header switches between the two sections (Vachanamrut Quiz / પ્રાપ્તિનો વિચાર). Content is static in `public/data/prapti.json` (`days[]`: `from`/`to` date range — normally 3 days — title, intro, prasangs, vichar prompts). Old entries are never replaced; each open range is a tab (newest first), and the page opens on the range containing today, else the latest earlier one. A 15-minute timer marks the day done in storage (`praptiDone`). Prasang text is quoted from the source named in `source` (paragraphs split by 
). Add the next range by appending an object; a range whose `from` is in the future is hidden (no tab, URL falls back) and appears automatically on its start date (user's local date), so content can be added ahead of time; `disabled: true` keeps a range locked regardless (e.g. a placeholder with only `from`/`to`).
- **Quiz visibility / admin page** (`#/enabledisablequizes`, `components/Admin.jsx`, not linked anywhere): `public/data/quiz-config.json` (`{ disabled: [baseId…] }`, base id = quiz id without the `en-` prefix, so one switch covers both languages). `App.jsx` loads it with `cache: 'no-store'` and drops disabled quizzes from `data.quizzes` before anything renders, so they vanish from Home (empty tabs/section chips hidden), practice, subject pages, the title index and direct `#/quiz/<id>` links; the admin page gets the unfiltered data. The page is gated by an access code checked in the browser against its SHA-256 (`CODE_HASH`; the plain code is not in the repo) — a deterrent only. Save commits the file through the GitHub contents API with a fine-grained token stored only in that browser (`storage.js` admin helpers); Vercel then redeploys. New quizzes are visible by default.
- **Pravachan library** (`#/pravachan[/<id>[/<itemKey>]]`, `components/Pravachan.jsx`): a tab of the admin page (tabs: on/off, create special quiz, pravachan) and behind the same access code (session unlock). Content is static in `public/data/pravachan.json` (`pravachans[]`: id, subject, title, subtitle, kind, date, duration, source, `sections[]` of `{heading, items[]}`; item `type` is `p`, `quote` or `prasang` (with `title`), paragraphs split by 
). Text is transcribed exactly from the source PDFs. The list page groups by subject; search covers every item across all pravachans (ignores ZWNJ and ્), with subject chips and a prasangs-only filter; results link to `#/pravachan/<id>/<sectionIdx>-<itemIdx>`, which scrolls to and flashes that item. Add a pravachan by appending an object.
- **અધિવેશન પ્રસંગ section** (`#/adhiveshan[/<n>]`, `components/Adhiveshan.jsx`): the 100 Satsang Prasang of North America Adhiveshan 2025, copied exactly from anirdesh by `scripts/build-adhiveshan.mjs` (title + paragraphs per prasang, categories from the page's side menu; inline tags dropped). One file per language, fetched for the current language. List grouped by the 8 categories, search across titles and text (shared helpers in `src/textSearch.jsx`, also used by the pravachan page), reading view with previous/next and a link to the anirdesh page.
- **Special (custom) quizzes** (`kind: 'custom'`, Home tab ખાસ ક્વિઝ, `src/customQuizzes.js`, builder `components/Custom.jsx` on the admin page's create tab `#/enabledisablequizes/create`, which saves straight to GitHub switched on or off): the admin picks Vachanamrut, question kinds and size, generates a fixed question set from **all** questions (hidden quizzes included; round-robin per Vachanamrut, deduped by id), previews it and adds it. Saved in `quiz-config.json` as `custom: [{id: 'custom-…', title, titleEn?, nos, questions: [questionId…], created}]`; new ones start in `disabled` until switched on. App rebuilds them per language from question ids (shared across gu/en; Gujarati-only content questions are skipped in English) and scores them like other quizzes. While the admin page is unlocked, `#/quiz/<id>` also opens hidden quizzes for preview. Config is written UTF-8-safe (base64 via TextEncoder).
- **Live games** (Kahoot-style, host-paced): host screen is the admin tab `#/enabledisablequizes/live` (`components/LiveHost.jsx`, any quiz incl. hidden/special), players join on `#/live` (`components/LivePlay.jsx`) with a 4-digit code and a name; final `components/Podium.jsx` (gold/silver/bronze). Shared state lives in Firebase Realtime Database (`src/live/live.js`, SDK loaded on demand; anonymous auth); schema documented at the top of `live.js`, security rules in `live-database-rules.json` (host-only meta/secret/scores, players write only their own entry and one answer per open question). Correct answers are kept in `secret` until the host reveals them; the host computes scores (1000 → 500 points by answer speed). The host tab keeps a per-browser history (localStorage `vachanamrut-quiz:live-history`) of games it created to reopen or delete them; games older than 24 h are deleted when a new game is created, and the podium has an end-and-delete button (only the creating browser's anonymous user may delete a game). The web config is not committed: `src/live/firebaseConfig.js` reads the JSON from the `VITE_FIREBASE_CONFIG` env var (`.env.local` locally, Vercel → Settings → Environment Variables for the site; both `.env*.local` and `src/firebaseconfig.txt` are git-ignored). Unset → the feature is off (no Home button). Firebase project: akshargnan-c8fb8 (Spark plan, anonymous auth, Realtime Database with the rules file published).
- **ગુરુહરિ આશીર્વાદ વિડિયો section** (`#/videos[/<view>[/<key>]]`, `components/Videos.jsx`): the Guruhari Ashirwad YouTube playlist (PLOX7n0cygMYA19eaokQqliIzEhz--1BoK). `scripts/guruhari-videos.json` is the video list (id, title; from a playlist export, not scraped); `scripts/build-videos.mjs` parses date/place/session/occasion from titles and assigns subjects: Vachanamrut discourses ("Vachanamrut Gadhada Madhya 15 (Part 2)") get `vachno` and that Vachanamrut's subjects from `data.subjects`; other titled topics are classified by hand in `scripts/video-topics.mjs` (site subject ids + `EXTRA_SUBJECTS` sabha themes; the build lists unclassified topics). Most videos (~1,180) have no topic in the title and get no subject — browsed by year/place/search. Views: subject, Vachanamrut, festival, year, place; cards play in a youtube-nocookie embed at the top of the page. To refresh: replace `guruhari-videos.json` with a new export, classify new topics, run `build-videos`.
- **Video suggestions**: under the player on `#/videos`, visitors suggest keywords/a વિષય (max 5/day per browser) → Firebase `suggestions/<pushId>` (`{video, text, subject?, at}`; rules: anyone may create a ≤300-char entry, only `admins/<uid>: true` may read/delete). Admin tab `#/enabledisablequizes/suggestions` (`components/Suggestions.jsx`) shows the browser's Firebase uid to register under `admins` in the console; Approve merges the words/subject into `public/data/video-tags.json` (`{videoId: {keywords, subjects}}`) via the GitHub contents API and deletes the suggestion; Reject, “delete older than 30 days” and “delete all” remove them. `Videos.jsx` merges video-tags.json into the videos (tags shown, searchable, subjects added).
- Theme: `data-theme` attribute on `<html>`, null means follow system preference; styles in `styles.css`.
